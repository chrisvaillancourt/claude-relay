# relay

A Claude Code mod (function-hook plugin): `/relay` runs a save turn, forks a continuation prompt, compacts, then fills the prompt box. `README.md` is the user-facing spec; keep it in step with any behavior change in the same commit.

## Layout

- `hooks/prompts.ts`: pure text and parsing (`notePathFor`, `promptPathFor`, `savePrompt`, `extractNote`, `taggedNote`, `runKey`, `isRunRecord`, `restartNotice`, `resumedNoteNotice`, `continuationPrompt`, `cleanContinuation`, `forSubmit`, `isHeldOrigin`, `isPersonOrigin`, `heldNotice`, `isCanceled`, `parseArgs`). No `$`. Unit-tested in `prompts.test.ts`.
- `hooks/register.ts`: wiring. Hooks (`session.start`, `turn.start`, `turn.complete`, `prompt.submit`, `command.run`), the run's state machine, the hold, timers, logging.
- `types/index.d.ts`: types and the `$.state` contract (`PluginState['relay']`: `run` and `hold`). Every `$.state` key the module uses must be declared here.
- `.claude-plugin/plugin.json`: manifest and `userConfig`. `marketplace.json` makes the repo its own marketplace.
- `.claude-plugin/types/` and `tsconfig.json` are generated by Claude Code when the mod loads. They're gitignored; don't commit or hand-edit them.

## Commands

```sh
claude plugin validate .
claude plugin test .
```

Both must pass before every commit. A behavior change needs a test in `hooks/*.test.ts` that fails without it.

## Design invariants

- **Engine constraints, found the hard way:**
  - `$.prompt.submit` is refused from inside a `command.run` hook (it would wait on the turn the hook holds). Submit from a `$.clock.after(0, …)` timer.
  - `$.session.compact` rejects while a turn runs, so the continuation starts from a timer after `turn.complete`. In live tests the first attempt succeeded; a rejection is retried twice (interactive only) and logged to the debug log. Headless sessions reject it outright ("not available in a headless session yet").
  - A plugin's submitted prompt never expands `@` mentions. That's why `fill` is the default delivery.
  - `$.model.fork` replays the last request, which ends before the turn's final answer, so the note (from `turn.complete`'s `answer`) is quoted into the fork prompt.
  - The plugin, not the model, writes the handoff note (`$.fs.write` creates directories). A model `Write` outside the project raises a permission prompt. Models add chatter around the note despite instructions, so the note is asked for inside `<handoff-note>` tags, each on its own line, and `extractNote` keeps only the inside. It takes the last block whose tags sit on their own lines, outside code fences: a model may quote the tag names in prose before the real note (a first-match regex once returned that prose), and a note may hold a fenced draft that shows the tags.
  - A compaction the person cancels rejects with "Compaction canceled."; `isCanceled` stops the run instead of retrying. The test kit can't make a mocked event reject with chosen text (a throwing hook is skipped and the kit's fallback error surfaces), so that rule is unit-tested as a pure function.
  - The engine already prefixes `$.ui.status`, `$.ui.toast` and command output with the plugin name; don't add `relay:` there. `$.ui.log` text reached a headless host unprefixed (not checked in the terminal), so log lines keep `relay:`.
- **Phases:** `idle → saving → continuing → idle`. The save turn is the first main-loop `turn.start` whose text carries `SAVE_MARKER`; only that turn's `turn.complete` continues the run. Subagent and teammate turns (`e.agentId` set) are ignored at both `turn.start` and `turn.complete`: on 2.1.312 they raise `turn.start` too (2.1.294 didn't), and one counted there would stop a run or end the hold early.
- **No step runs after a failed one.** A failed or interrupted save turn or fork must not compact. A main-loop turn that starts after the save turn stops the run before compaction.
- **The box is filled as compaction starts** (`fillDuringCompaction`, default on), so the person can queue the prompt before a background task finishes. So a failed or skipped compaction leaves the prompt in the box, and its message must say to run `/compact` before sending it. With the option off, a failed or skipped compaction fills nothing. That Enter during a compaction queues the prompt is the engine's behavior, which the test kit can't show and the API types don't state; check it live after changing this (the README records the last check).
- **Background deliveries are held** (`holdAtom` in `$.state`) from the save turn's `turn.start` until the next main-loop `turn.start` after the person's prompt. A `prompt.submit` whose origin `isHeldOrigin` and that carries no `turnId` is appended inside the atom update (`holdAppend`, so one racing a release passes instead of vanishing) and dropped. The person's prompt (`isPersonOrigin`; not one typed into the save turn) takes the items as `context` and sets `endsAtTurn`. Refused further down, `restoreHold` gives them back only if the hold's `gen` is unchanged (a cancel or new run bumps it) and only if that prompt was the one that set `endsAtTurn`. What arrives between that Enter and its turn's start is resubmitted as relay's message at that `turn.start`. A run that fails with nothing in the box, `/relay cancel` (any phase) and a new `/relay` (into its save prompt, taken when that prompt is sent, so a cancel first releases it) release what's held; a failed fill keeps holding. Any hand-back that's refused or fails goes to the log in full (`logHeld`): never lost silently. Submit mode puts what's held in its own text, since a plugin's submit carries no context. Not held: `unclassified` (teammates; a person's unstamped command shares it) and `channel` (maybe the person, remotely). The hook is fail-open (`.catch` lets the prompt through).
- **A turn that starts after the save turn is latched** (`interruptedRunId`), so a quick turn that ends before a compaction retry still stops the run.
- **The generated continuation prompt is written beside the note** (`promptPathFor`), best effort, so it can be compared with what the person sent; the transcript keeps only the sent one.
- **`saving` can't hang.** Five seconds after the save prompt's turn starts, a run whose save turn wasn't matched stops.
- **`runId` guards stale work.** Cancel and every new run bump it; each async step re-checks `isCurrent` before acting.
- **Hot reloads reset module variables** (timers included); `$.state` and `$.store` survive. `session.start` resets a run a reload left `continuing` (its timer is gone); a `saving` run survives, since its next step is the save turn's `turn.complete`.
- **A new process loses `$.state` too.** An upgrade can move a `--bg` session to a new process mid-turn (seen 2026-10-27 on 2.1.311 → 2.1.312; the transcript resumes with "Continuing an interrupted response", and `$.session.id()`, the transcript's name, stays the same). So each run in progress is also recorded in `$.store` under `run/<session id>` (`RunRecord`: `saving` from `/relay`, `continuing` once the note is written), and every end of a run (`finish`, cancel, a reload's reset) deletes it. `session.start` with an idle `$.state` and a record for this session logs the lost run. For a `saving` record, the first main-loop `turn.complete` after that is taken as the resumed save turn: if it carries a tagged note (`taggedNote`, no whole-message fallback), relay writes it to the note path and says to `/compact` and send it. Nothing is forked or compacted. Records older than a week are pruned at `session.start`. The engine gives no signal for a new process or a resumed turn, hence the record.
- Reporting is best effort and must never throw out of a hook or timer.

## Conventions

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`).
- Bump `version` in `plugin.json` for every release that GitHub installs should get; a folder-marketplace install reads the clone directly.
- MIT licensed: `LICENSE` at the root, and `plugin.json` says `MIT`. The repo is public, so keep personal paths, secrets and work details out of files and commit messages.
- Don't add Claude or AI attribution trailers to commits.
